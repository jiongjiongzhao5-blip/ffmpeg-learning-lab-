# README – H.264 Annex-B 格式 NALU 解析器

这是一个**轻量级、零拷贝的 H.264 码流解析工具**。  
它能够读取一段 H.264 原始码流（Annex-B 格式），自动分割出其中的每一个 **NALU（网络抽象层单元）**，并解析出每个 NALU 的类型、重要性、起始码长度、载荷大小等关键信息。

---

## 1. 用途

- **学习 H.264 码流结构**：通过实际解析，直观理解 NALU 的组成（起始码 + 头部 + 载荷）。
- **调试视频编码数据**：当你需要检查视频文件中的 SPS、PPS、IDR 帧等是否正常时，可以用它快速查看。
- **开发视频处理工具的前置步骤**：比如后续需要提取 SPS/PPS 参数、过滤特定类型的 NALU，或进行码流编辑。
- **纯教育目的**：展示如何在不依赖 FFmpeg 等大库的情况下，手动解析 H.264 码流。

---

## 2. 你需要什么

- **C++ 编译器**：支持 C++11 或更高版本（使用了 `std::vector`、`enum class`、`nullptr` 等）。
- **无需任何第三方库**：所有代码仅依赖标准 C++ 库（`iostream`、`vector`、`cstdint` 等）。
- **一段 H.264 裸流数据**：本程序在 `main` 函数中内置了一段模拟数据，方便直接运行演示。你也可以修改代码，从文件或网络读取真实码流。

## 3. 程序能完成什么

| 功能点                 | 说明                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **自动寻找所有 NALU**  | 在给定的内存块中，通过扫描起始码（`0x000001` 或 `0x00000001`），分割出每一个完整的 NALU。 |
| **解析 NAL 头部**      | 提取 1 字节头部中的三个字段：<br>• `forbidden_zero_bit`（必须为 0）<br>• `nal_ref_idc`（重要性，0~3）<br>• `nal_unit_type`（NALU 类型，例如 7=SPS, 8=PPS, 5=IDR） |
| **零拷贝设计**         | 不复制任何数据，只记录指针和长度，性能极高，适合处理大文件。 |
| **支持两种起始码长度** | 兼容 3 字节（`0x000001`）和 4 字节（`0x00000001`）起始码，常见于各种编码器输出。 |
| **输出结构化信息**     | 对每个 NALU 输出类型、重要性、起始码长度、总大小和载荷大小，方便后续处理。 |

你可以轻松识别出三个 NALU 的类型和大小。

## 4. 工作原理（通俗版）

### 4.1 H.264 码流的基本概念

H.264 视频压缩后的数据被组织成一个个 **NALU（网络抽象层单元）**。每个 NALU 是一个独立的数据包，包含了一部分视频信息（比如一帧图像的一部分，或者全局参数）。  
这些 NALU 在存储或传输时，需要一种方式将它们分隔开。**Annex-B 格式** 就是最常用的一种，它使用特殊的 **起始码（Start Code）** 来标记每个 NALU 的开始。

- **起始码** 有两种形式：
  - 三字节：`0x00 0x00 0x01`
  - 四字节：`0x00 0x00 0x00 0x01`
  
  四字节起始码通常用于文件开头，或为了对齐目的，但两者在解析时都需识别。

- **NALU 结构**：  
  `[起始码] [1字节头] [载荷数据]`

  - **1字节头** 的位布局：
    - bit 7：`forbidden_zero_bit`（必须为 0，否则码流错误）
    - bit 6-5：`nal_ref_idc`（表示该 NALU 的重要性，值越大越不能丢弃）
    - bit 4-0：`nal_unit_type`（表示 NALU 的类型，如 7=SPS, 5=IDR 等）

- **载荷数据**：是除去起始码和头部后的剩余字节，具体内容由类型决定（例如 SPS 包含编码参数，IDR 包含完整的图像数据）。

### 4.2 解析过程（三步走）

1. **扫描起始码**  
   `find_start_code` 函数从数据开始逐个字节移动窗口，一旦发现 `0x00 0x00` 后跟着 `0x01`（3字节起始码）或 `0x00 0x01`（4字节起始码），就记录下起始码的位置和长度。

2. **分割 NALU**  
   找到两个连续的起始码，它们之间的所有数据（包括前一个起始码，但不包括后一个起始码）就构成一个完整的 NALU。  
   - 如果只有一个起始码，则从该起始码到数据末尾视为最后一个 NALU。

3. **解析 NAL 头部**  
   对每个 NALU，跳过起始码后读取 1 个字节，按位解析出三个字段，并记录下载荷数据的起始地址和长度（跳过起始码和头部）。

整个过程不复制数据，只记录指针和长度，因此对内存非常友好。

### 4.3 零拷贝的优势
在大型视频文件（例如几十 GB）中，如果每解析一个 NALU 就复制一份数据，会极大消耗内存和 CPU。本程序只记录偏移和大小，后续如果需要处理载荷，可以直接用指针操作，无需额外空间。

## 5. 如何编译和运行

### 5.1 编译
使用任意 C++11 编译器（如 g++、clang、MSVC）：
```bash
g++ -std=c++11 -o annexb_parser main.cpp
```
（Windows 下可用 Visual Studio 或 MinGW 编译）

### 5.2 运行
直接执行：
```bash
./annexb_parser
```
程序会输出内置测试数据的结果。如果你想解析自己的码流文件，可以修改 `main` 函数，用 `fopen`/`fread` 将文件读入 `std::vector<uint8_t>`，再调用 `parse_stream`。

## 6. 程序结构简介

| 组件                    | 说明                                                         |
| ----------------------- | ------------------------------------------------------------ |
| `NalUnitType` 枚举      | 定义了 H.264 标准中常用的 NALU 类型（1~12），方便可读性。    |

| `main` 函数             | 构造一个模拟码流，调用解析器并打印结果，作为演示。           |

## 7. 局限性 & 扩展建议

| 局限性                 | 说明                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **仅演示内存数据**     | 目前代码内置了测试数据，未提供从文件读取的接口，但你可以轻松添加。 |
| **未处理“防竞争字节”** | H.264 标准中，为防止载荷中出现类似起始码的序列，编码器会插入 `0x03`（防止竞争）。本程序未剥离这些字节，因此解析出的载荷是原始码流（包含 `0x03`）。若需处理，可在解析后手动移除。 |
| **不支持 AVCC 格式**   | 这是另一种常见的封装格式（如 MP4 文件内部），起始码被替换为长度前缀。本程序只适用于 Annex-B。 |

### 你想继续扩展的话，可以：
- **添加文件输入功能**：用 `std::ifstream` 读取二进制文件，将内容传递给 `parse_stream`。
- **按类型过滤 NALU**：例如只提取 SPS/PPS，或统计 IDR 帧数量。
- **去除 `0x03` 防竞争字节**：在解析后对载荷数据进行还原。
- **支持 HEVC (H.265)**：类似原理，但起始码和头部结构略有不同，可参考本实现修改。
