# README – 音频解码与重采样 Pipeline

这是一个**完整的音频解码、重采样和输出工具**。  
它能够读取 FLV（或其他容器）文件中的音频流，将其**解码为原始 PCM 数据**，并**重采样为统一的 44.1kHz 立体声 16 位整型（S16）格式**，最终输出为无头的 `.pcm` 文件，可被 ffplay 等播放器直接播放。

---

## 1. 用途

- **从视频文件中提取纯净音频**：将 FLV、MP4 等容器中的音频（如 AAC、MP3）解码为未压缩的 PCM，便于后续音频处理（如编辑、混音、分析）。
- **统一音频格式**：不同来源的音频采样率、声道数、位深各异，本工具将它们统一为标准格式，方便批量处理或播放。
- **学习 FFmpeg 解码与重采样流程**：代码完整展示了如何用现代 FFmpeg API（`AVChannelLayout`）实现解封装→解码→重采样→输出的全流水线。
- **验证音频流完整性**：通过生成 PCM 文件并用播放器回放，可快速检查音频内容是否正常。

## 2. 你需要什么

### 2.1 系统环境
- **操作系统**：Windows、Linux、macOS 均可（跨平台 C++ 程序）。

## 4. 工作原理（通俗版）

### 4.1 音频在媒体文件中的“旅行”
一个媒体文件（如 FLV）相当于一个快递包裹，里面装着压缩过的音频数据（比如 AAC 编码）。压缩数据体积小，但播放器不能直接播放，必须先“拆包”并“还原”成原始声音波形。

本程序就是完成这个“拆包→还原→统一格式”的流水线，分为四个步骤：

1. **解封装（Demuxing）**  
   从容器中分离出音频流的数据包（每个包是一段压缩音频，如一个 AAC 帧）。

2. **解码（Decoding）**  
   将压缩数据包还原为原始的 PCM 样本（即未压缩的声音波形）。解码后的格式取决于原始编码（可能是浮点型、整型，声道布局也可能不同）。

3. **重采样（Resampling）**  
   将解码后的 PCM 转换为统一的目标格式：**采样率 44100 Hz、立体声（2 声道）、有符号 16 位整型（交错存储）**。这一步包含三个子操作：
   - **采样率转换**：例如从 48000 Hz 降到 44100 Hz。
   - **声道转换**：例如从单声道（1 声道）转为立体声（2 声道），或从 5.1 环绕声下混为立体声。
   - **格式转换**：例如从浮点型（`AV_SAMPLE_FMT_FLTP`）转为整型（`AV_SAMPLE_FMT_S16`）。

4. **写入文件**  
   将重采样后的 PCM 数据按二进制方式连续写入 `.pcm` 文件（不添加任何头部信息，即“裸 PCM”）。

### 4.2 为什么输出固定为 44.1kHz / 立体声 / S16？
- **44.1kHz** 是 CD 音质标准，也是绝大多数播放器默认支持的采样率。
- **立体声** 是最常见的声道配置，兼容性最好。
- **S16（16 位有符号整型）** 是许多音频处理库和硬件设备的原生格式，且文件大小适中（相比浮点型更省空间）。

固定格式让后续处理（如用 `ffmpeg` 转成 MP3、用 Python 分析波形）变得非常简单，无需再关心输入参数。

### 4.3 重采样器的延迟初始化
由于某些编码格式（如 AAC）的声道布局在文件头中可能不明确，直到解码出第一帧才能确定，程序采用**延迟初始化重采样器**的策略：只有在成功解码出第一帧后，才根据该帧的实际参数创建重采样器。这样能保证参数 100% 准确。

### 4.4 冲刷（Flush）机制
解码器内部可能缓存了若干帧（尤其是带 B 帧的音频格式，或解码器本身有延迟）。当文件读取完毕后，必须发送一个 `nullptr` 包给解码器，让其“吐出”所有缓存帧，否则会丢失音频末尾的数据。

## 5. 程序结构详解

| 组件                         | 说明                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| **RAII 删除器**              | 为 `AVFormatContext`、`AVCodecContext`、`AVPacket`、`AVFrame`、`SwrContext` 分别定义删除器，配合 `unique_ptr` 自动释放。 |
| `log_ffmpeg_error`           | 将 FFmpeg 错误码转换为可读字符串并打印。                     |
| `AudioDecoderPipeline` 类    | 封装所有核心逻辑，对外只暴露 `init()` 和 `process()` 方法。  |
| `init()`                     | 打开文件、探测流信息、查找音频流、初始化解码器、分配 Packet/Frame。 |
| `process()`                  | 循环调用 `av_read_frame` 读取数据包，调用 `decode_and_resample` 处理，最后冲刷解码器。 |
| `decode_and_resample()`      | 将数据包送入解码器，循环接收解码帧，对每个帧调用 `init_resampler_if_needed`（若未初始化），执行重采样并写入文件。 |
| `init_resampler_if_needed()` | 使用 `swr_alloc_set_opts2` 创建重采样器，设置输入/输出参数，调用 `swr_init` 完成初始化。 |
| **主函数**                   | 解析命令行参数，创建 Pipeline 对象，依次调用 `init()` 和 `process()`，最后提示播放命令。 |

## 6. 如何编译和运行

### 6.1 安装 FFmpeg 开发库（以 Ubuntu/Debian 为例）
```bash
sudo apt update
sudo apt install libavformat-dev libavcodec-dev libswresample-dev libavutil-dev
```
其他系统（macOS Homebrew、Windows vcpkg 等）请按对应方式安装。

### 6.2 编译（Linux/macOS）
```bash
g++ -std=c++17 -o audio_decoder main.cpp \
    -lavformat -lavcodec -lswresample -lavutil \
    -pthread -lz -lm
```
（Windows 下需链接对应的 `.lib` 文件，可参考 FFmpeg 官方构建指南）

### 6.3 运行
```bash
./audio_decoder input.flv output.pcm
```
- 第一个参数：输入媒体文件（支持 FLV、MP4、MKV 等）。
- 第二个参数：输出 PCM 文件（扩展名通常为 `.pcm` 或 `.raw`）。

如果省略参数，程序会尝试使用默认文件名 `cctv1.flv` 和 `output.pcm`（但建议显式指定）。

### 6.4 验证输出
程序运行后会提示一条 `ffplay` 命令，复制执行即可试听：
```bash
ffplay -ar 44100 -ac 2 -f s16le output.pcm
```
如果听到正常声音，说明解码重采样成功。

## 7. 局限性 & 扩展建议

| 局限性                       | 说明                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| **输入格式依赖 FFmpeg 支持** | 若 FFmpeg 未编译某些解码器（如某些专有格式），程序可能失败。 |
| **只处理第一条音频流**       | 如果文件有多条音轨，仅选择“最佳”的一条，无法通过参数选择。可扩展为命令行选项指定流索引。 |
| **输出固定为 PCM**           | 不提供压缩编码输出，若需 MP3/AAC 等，需额外编码器（可增加 `libavcodec` 编码部分）。 |
| **未处理时间戳**             | 输出文件不保留时间信息，纯 PCM 不包含帧边界，播放时需指定参数（`-ar`、`-ac`、`-f`）。 |
| **重采样质量固定**           | 使用默认重采样算法（可能为快速但略低质量），可调整 `swr_convert` 选项以追求更高音质。 |

### 你想继续扩展的话，可以：
- **添加参数选择**：通过命令行选项指定输出采样率、声道数、采样格式。
- **支持输出压缩格式**：在重采样后接入编码器（如 `libmp3lame`）直接生成 MP3。
- **增加进度显示**：根据已处理数据包数量或文件百分比显示进度条。
- **支持更复杂的声道布局**：比如从 5.1 下混为立体声时，可调整下混矩阵系数。
