# README – 视频解码器（YUV420P 提取器）

这是一个**轻量级、高效的视频解码工具**。  
它能够将任意媒体文件（MP4、FLV、MKV、AVI 等）中的 **视频流解码为原始 YUV420P 格式**，输出标准的 `.yuv` 文件，可用于视频分析、编码测试或作为后续处理（如滤镜、转码）的输入。

---

## 1. 用途

- **提取原始视频数据**：方便查看视频的每一帧像素值，用于调试编码器或分析图像内容。
- **生成标准 YUV 测试序列**：将解码后的 YUV 文件提供给编码器进行压缩测试。
- **学习视频解码流程**：代码完整展示了使用 FFmpeg 进行解封装→解码→写入原始帧的全过程，是理解视频解码管道的绝佳范例。
- **配合其他工具进行图像处理**：YUV 文件可被 FFmpeg、ImageMagick 等工具直接读取，也可用 Python 进行逐帧分析。

## 2. 你需要什么

### 2.1 系统环境
- **操作系统**：Windows、Linux、macOS 均可（跨平台 C++ 程序）。

- **FFmpeg 开发库**（版本 4.0 或更高）：
  - `libavformat`（解封装）
  - `libavcodec`（解码）

- **一个包含视频流的媒体文件**（任何 FFmpeg 可解码的编码格式，如 H.264、HEVC、VP9 等）。

## 3. 程序能完成什么

| 功能点                      | 说明                                                         |
| --------------------------- | ------------------------------------------------------------ |
| **自动探测媒体格式**        | 通过 `avformat_open_input` 自动识别文件类型，无需手动指定。  |
| **智能选择视频流**          | 如果文件包含多条视频轨（如不同分辨率），程序自动选择“最佳”的那一条。 |
| **解码任意支持的视频编码**  | 只要 FFmpeg 编译了对应解码器（H.264、H.265、VP9、AV1 等），程序就能解码。 |
| **输出为 YUV420P 格式**     | 将解码后的帧统一转换为 **YUV420P**（Planar 4:2:0）格式，这是大多数视频编码器使用的原生格式。 |
| **正确处理内存对齐**        | 按每行的 `linesize`（行步长）逐行写入，避免因内存填充导致的绿边或花屏现象。 |
| **完整的冲刷（Flush）机制** | 在文件读取结束后，冲刷解码器缓存，确保所有帧都被输出，不丢失尾部数据。 |
| **RAII 资源管理**           | 使用 `std::unique_ptr` 管理所有 FFmpeg 资源，即使发生异常也能自动释放，杜绝内存泄漏。 |

### 典型运行示例
```bash
./video_decoder input.mp4 output.yuv
```
输出文件 `output.yuv` 可使用以下命令播放预览：
```bash
ffplay -f rawvideo -pixel_format yuv420p -video_size 1920x1080 output.yuv
```
> 注意：`-video_size` 需替换为视频的实际宽高（程序会在控制台打印，也可用 `ffprobe` 获取）。

## 4. 工作原理（通俗版）

### 4.1 从压缩到原始像素
视频文件中的视频流是经过压缩编码的（如 H.264），以减少存储和传输体积。播放时需要先**解码**，将压缩数据还原为原始的像素矩阵（即 YUV 图像）。  
本程序就是完成这个“解压”过程，并将每一帧的像素数据原样保存到文件中。

### 4.2 YUV 色彩空间简介
YUV 是一种颜色编码方法，将亮度（Y）和色度（U、V）分离：
- **Y** 分量：亮度信息，对应灰度图像。
- **U 和 V** 分量：色度信息，描述颜色。

YUV420P 是一种常见的格式，其中：
- Y 平面大小为 `width × height` 字节。
- U 和 V 平面大小均为 `(width/2) × (height/2)` 字节。
- 三个平面分别存储，互不交错（Planar 模式）。

### 4.3 解码流程（5 步详解）

1. **打开文件并探测格式**  
   `avformat_open_input` 读取文件头，识别封装格式（如 MP4），创建 `AVFormatContext`。

2. **获取流信息**  
   `avformat_find_stream_info` 解析出视频流的编码参数（宽高、像素格式、帧率等）。

3. **查找并初始化解码器**  
   `av_find_best_stream` 自动定位视频流并返回对应的解码器。  
   然后分配解码器上下文（`AVCodecContext`），将流的编码参数拷贝进去，最后调用 `avcodec_open2` 打开解码器。

4. **循环读取数据包并解码**  
   - 使用 `av_read_frame` 逐个读取压缩数据包（`AVPacket`）。  
   - 仅处理属于视频流的包，将其送入解码器（`avcodec_send_packet`）。  
   - 循环调用 `avcodec_receive_frame` 获取解码后的原始帧（`AVFrame`）。  
   - 若帧的像素格式为 YUV420P，则调用 `write_yuv420p_frame` 写入文件。

5. **冲刷解码器**  
   当所有数据包读取完毕后，发送 `nullptr` 给解码器，强迫其输出所有缓存的帧（有些解码器会延迟输出）。这一步确保不丢失任何帧。

### 4.4 关于 `linesize` 的注意事项
解码器分配的图像缓冲区每行可能并非连续排列，为了 CPU 对齐，每行的实际字节数（`linesize`）通常大于或等于图像宽度。  
**如果直接将整个 `data[0]` 指向的连续内存写入文件，就会包含填充的无关数据，导致图像出现绿色条纹或花屏。**  
本程序严格按照每行的有效宽度逐行写入，确保输出文件干净、正确。

### 4.5 RAII 资源管理
代码为 `AVFormatContext`、`AVCodecContext`、`AVPacket` 和 `AVFrame` 分别定义了删除器，并使用 `std::unique_ptr` 包装。这样，即使在解码过程中出错提前返回，所有资源也能被自动释放，无需手动 `goto` 或层层释放。

## 5. 如何编译和运行（Visual Studio 配置）

### 5.1 下载 FFmpeg 开发包
- 推荐从 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 或 [BtbN](https://github.com/BtbN/FFmpeg-Builds/releases) 下载 **Shared** 或 **Dev** 版本，解压到一个目录（如 `C:\ffmpeg`）。

### 5.2 创建 Visual Studio 项目
1. 新建一个 **控制台应用（C++）** 项目。
2. 将本程序的 `main.cpp` 添加到源文件。
3. 配置项目属性：
   - **C/C++** → **附加包含目录**：添加 FFmpeg 的 `include` 路径（如 `C:\ffmpeg\include`）。
   - **链接器** → **附加库目录**：添加 FFmpeg 的 `lib` 路径（如 `C:\ffmpeg\lib`）。
   - **链接器** → **附加依赖项**：添加 `avformat.lib`、`avcodec.lib`、`avutil.lib`。
4. 选择与 FFmpeg 库匹配的平台（x64 / Win32）。
5. 编译生成 `video_decoder.exe`。

### 5.3 运行
将 FFmpeg 的动态库（`.dll`）复制到 `.exe` 所在目录（或加入系统 PATH），然后在命令行执行：
```bash
video_decoder.exe input.mp4 output.yuv
```

## 6. 程序局限性 & 扩展建议

| 局限性                           | 说明                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| **仅输出 YUV420P**               | 如果解码器输出其他像素格式（如 NV12、RGB），程序会跳过该帧。可添加像素格式转换（使用 `sws_scale`）来支持更多格式。 |
| **忽略音频**                     | 只处理视频流，音频数据被丢弃。若需要音频，可结合之前的“音频解码器”工具。 |
| **不保留时间信息**               | YUV 文件不含帧率、时长等信息，播放时需手动指定宽高和像素格式。 |
| **对大文件可能占用较多磁盘空间** | 原始 YUV 文件体积巨大（一分钟 1080p YUV420P 约 1.5GB），请确保有足够空间。 |

### 你可以进一步扩展的功能：
- **添加像素格式转换**：使用 `libswscale` 将任意格式转为 YUV420P，兼容更多输入。
- **支持输出为 PNG/JPEG 序列**：使用 `libavcodec` 编码器将每一帧编码为图片文件。
- **添加进度显示**：根据已处理帧数或文件百分比输出进度。
- **支持指定输出分辨率**：通过 `sws_scale` 进行缩放，生成不同尺寸的 YUV 文件。
