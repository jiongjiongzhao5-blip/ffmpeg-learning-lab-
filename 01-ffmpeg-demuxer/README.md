# README – FFmpeg 媒体文件解复用演示程序

## 1. 用途
这个程序是一个**极简但完整的媒体文件解复用（Demuxing）示例**。它的核心任务是：
- 打开一个本地媒体文件（如 `.mp4`、`.mkv`、`.avi`、`.flv` 等）
- 读取文件中所有的“数据包”（Packet）
- 分别统计**视频包**和**音频包**的数量及总大小
- 将前 5 个视频包的详细信息打印出来（时间戳、关键帧标志、大小等）

简单说：**它帮你“拆开”媒体文件，看看里面到底装了哪些视频和音频小块，以及它们的体积和时间分布**。

## 2. 你需要什么

### 2.1 系统环境
- **操作系统**：Windows / Linux / macOS 均可（本程序使用标准 C++ 和 FFmpeg 跨平台库）。

### 2.2 必备依赖
- **FFmpeg 库**（必须）：  
  程序使用了 FFmpeg 的 `libavformat`、`libavcodec`、`libavutil` 三个组件。你需要先安装 FFmpeg 的开发包（包含头文件和动态/静态库）。

  - **Ubuntu/Debian**：`sudo apt install libavformat-dev libavcodec-dev libavutil-dev`
  - **CentOS/RHEL**：`sudo yum install ffmpeg-devel`
  - **macOS (Homebrew)**：`brew install ffmpeg`
  - **Windows**：下载预编译的 FFmpeg 开发包（如从 BtbN 或 gyan.dev），配置好包含目录和库目录。

- **C++ 编译器**：支持 C++11 或更高（因为用到了 `std::unique_ptr` 和 lambda）。

### 2.3 一个媒体文件
你需要准备一个本地媒体文件作为输入，比如 `video.mp4` 或 `movie.mkv`。程序运行时通过命令行参数传入。

## 4. 工作原理（通俗解说）

### 4.1 媒体文件是什么？
一个媒体文件（比如 `.mp4`）本质上是一个**容器**，里面装了很多“小盒子”：
- **视频流**（连续的画面数据，经过压缩编码，比如 H.264）
- **音频流**（连续的声音数据，压缩编码，比如 AAC）
- 可能还有字幕、章节等信息。

这些数据在容器里被切分成一个个**数据包（Packet）**，每个包携带一小段编码后的数据，并附有**时间戳**（告诉播放器这个包应该何时展示）。

### 4.2 程序的“解复用”过程
**解复用**就是**把容器里的各个流拆开，逐个取出数据包**，供后续解码或处理。这个过程像拆快递盒：外层是封装格式（MP4），里面分别装着视频包和音频包，程序按顺序一个个掏出来。

本程序的工作流程分为 6 步：

1. **打开文件**  
   `avformat_open_input` 会读取文件头部，识别封装格式，并创建一个 `AVFormatContext` 结构，它相当于整个文件的“档案夹”。

2. **获取流信息**  
   `avformat_find_stream_info` 会从文件里读一点数据，确定每个流的编码参数（如视频分辨率、音频采样率），并填入上下文。

3. **打印媒体摘要**  
   `av_dump_format` 是 FFmpeg 提供的调试工具，直接把文件的基本信息打印到控制台（方便你确认程序正确识别了文件）。

4. **寻找最佳视频/音频流**  
   媒体文件可能有多个视频流（如不同视角）或多个音频流（不同语言）。`av_find_best_stream` 会自动选择“最佳”的那个（一般默认是第一个、最高质量的）。程序得到流索引后，后面只统计这两个流。

5. **循环读取所有数据包**  
   `av_read_frame` 每次从文件中取出一个数据包（Packet），并根据它的 `stream_index` 判断属于视频还是音频。  
   - 如果是视频，就累加计数和字节数，且前 5 个包打印详细信息（时间戳从 `pts` 和流的时间基 `time_base` 换算成秒）。  
   - 如果是音频，只计数和累加字节数（为简化，不打印细节）。  
   - 处理完一个包后，必须调用 `av_packet_unref` 释放这个包占用的引用，否则内存泄漏。

6. **循环结束与统计**  
   当 `av_read_frame` 返回 `AVERROR_EOF` 表示文件读完，程序打印最终统计结果。

### 4.3 关键时间戳换算
每个包都有 `pts`（显示时间戳）和 `dts`（解码时间戳），它们是一个整数值，需要乘以流的 `time_base`（时间基）才能得到真实的秒数。  
例如 `time_base = 1/90000`（常见于 MPEG 系列），则 `pts=180000` 表示 `180000 * 1/90000 = 2.0` 秒。

### 4.4 资源自动管理（RAII）
FFmpeg 是 C 语言库，需要手动调用释放函数。本程序使用 C++ 的 `std::unique_ptr` 配合自定义删除器，在对象析构时自动调用 `avformat_close_input` 和 `av_packet_free`，保证**即使中途出错退出，资源也能被释放**，避免内存泄漏。

## 5. 如何编译和运行

### 5.1 编译命令示例（Linux/macOS）
假设 FFmpeg 已安装在系统默认路径：
```bash
g++ -std=c++11 -o demuxer main.cpp \
    -lavformat -lavcodec -lavutil \
    -pthread -lz -lm
```
（可能需要额外链接库，如 `-lssl -lcrypto`，取决于 FFmpeg 编译选项；Windows 下需指定库路径和库文件名）

### 5.2 运行
```bash
./demuxer /path/to/your/video.mp4
```

### 5.3 注意事项
- 如果文件路径包含空格，请用引号括起来。
- 若 FFmpeg 库不在默认路径，需用 `-I` 和 `-L` 指定头文件和库目录。

## 6. 程序局限性 & 扩展建议

| 局限性               | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| **仅读取，不解码**   | 本程序只分离出压缩数据包，不进行解码（即不恢复成原始图像/声音）。 |
| **只处理视频和音频** | 其他流（字幕、数据）被忽略，不会统计。                       |
| **不处理网络流**     | 虽然 FFmpeg 支持，但本程序未对网络协议做特殊处理，仅用于本地文件。 |
| **打印示例有限**     | 只打印了前 5 个视频包，你可修改 `if (video_pkt_count <= 5)` 中的数字来调整。 |

**如果你想扩展**：
- 可以添加解码功能，把视频包送给解码器，得到原始像素帧。
- 可以增加字幕流统计。
- 可以支持写入到另一个容器（重封装）。
- 可以增加命令行选项（如只统计视频，或只处理前 N 个包）。
