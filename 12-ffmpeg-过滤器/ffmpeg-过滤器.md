# 先搭一个"画面"，后面所有东西都往这个画面里装

把 FFmpeg 的滤镜系统想象成**一家生产挂历的工厂流水线**：

- **帧（Frame）** = 流水线上的**一张张照片**（要处理的图片或声音片段）
- **滤镜（Filter）** = 流水线上的**一台台机器**（比如"缩放机"把照片缩小、"翻转机"把照片上下颠倒、"合成机"把两张照片叠在一起）
- 机器之间靠**传送带**把照片从这台运到下一台
- 工厂里有个**总负责人**，他知道整条线有哪些机器、哪些传送带，统一指挥

好，现在记住这个画面。下面要讲的每个东西，都是这个画面里的一个具体角色。

---

# 一、先把 5 个最难懂的名词"翻译"成大白话

这几个词如果你没搞懂，后面全卡住。我们先单独解决它们。

### 名词1：什么是"结构体"？
就是**一个文件柜**，里面分了很多格子，每个格子放一类信息。
比如"传送带"这个结构体，里面就有格子放：这条带子一头连哪台机器、另一头连哪台机器、上面跑的照片是什么尺寸……把所有相关信息**捆在一个文件柜里**，方便统一管理。代码里叫 `struct`，就是"结构"的意思。

### 名词2：什么是"回调函数"？
就是**"到时候叫我"**。
比如你给快递员留句话："送到小区门口**打电话**叫我下楼。"——快递员到点了就打电话（**回调**你），而不是你一直守在门口傻等。
FFmpeg 也一样：框架自己不知道你的机器具体怎么干活，所以它给你留了几个"电话"：**"收到一张照片时叫我"、"需要我产出一张照片时叫我"**。你把自己写的函数"挂"上去，到时候 FFmpeg 自动替你拨通。这个"挂上去的函数"就是回调函数。

### 名词3：什么是"实例"？为什么要有"图纸"和"机器"两套东西？
这是新手最容易懵的地方。用一句话说清：

> **图纸（AVFilter）是"怎么造"的说明，机器（AVFilterContext）是"造出来正在干活"的那台。**

为什么非要分开？因为**同一张图纸可以造出很多台参数不同的机器**。
比如工厂有一张"缩放机图纸"（AVFilter = scale）。你可以照这张图纸造一台"缩到一半大小的机器"，再造一台"放大两倍的机器"——机器是两台，但图纸是同一张，不需要复制第二份。
所以：
- 全工程里，"缩放机图纸"只有一份 → 这就是 **AVFilter**
- 但你实际用的"这台缩一半的机器" → 这就是 **AVFilterContext**

### 名词4：什么是"接口 / 端口 / 插口"？
就是机器上的**进料口和出料口**。有的机器只有一个进口一个出口（比如缩放机），有的机器有**两个进口**（比如合成机，要同时接收两张照片）。代码里叫"Pad"（端口）。

### 名词5：什么是"格式"？为什么要"协商"？
"格式"就是照片的**"底子规格"**：多大（宽高）、用什么颜色编码（像素格式，比如 YUV、RGBA）、每秒几张（帧率）……
为什么要协商？举个例子：**A 机器产出的照片是 YUV 格式，但 B 机器只认 RGBA 格式**，两边语言不通，怎么办？必须**先商量出一个两边都认的格式**，再开始传照片。这个"商量"的过程就叫**格式协商（negotiation）**。FFmpeg 会在开工前自动做这件事，你不用手动做，但要理解它存在。

好，5 个名词解决了。现在正式开始讲 PDF 内容。

# 二、PDF1：《FFmpeg 过滤器框架分析》——拆开看流水线内部的每个零件

这份 PDF 干的事就一个：**把这套流水线的零件一个个拆开，告诉你每个零件是干嘛的**。一共有 6 个零件 + 2 个特殊机器。

## 零件1：AVFilterGraph —— 总负责人（管全局的大管家）

它就是那个"工厂总负责人"。它手里捏着两样东西（这是 PDF 标了重点的）：

1. **一份所有机器的名单**（代码里叫 `filters` 数组）：车间里有多少台机器（`nb_filters`），每台是谁。
2. **一整套车间级规定**：
   - 允许多线程干活吗？（`thread_type`，最大线程数 `nb_threads`）
   - 机器格式对不上时，要不要**自动插一台"格式转换机"**来兜底？（`scale_sws_opts` 是插转换机时的默认设置；`disable_auto_convert` 设为 1 就**禁止**自动插，这时格式对不上会直接报错，方便排查问题）
   - 还有一块"自留地" `opaque`：总负责人不管里面装啥，你想塞自己的私人物品进去也行。

> **一句话**：AVFilterGraph 自己不干活，它是"管谁在干活"的。就像车间主任，不搬货，但所有机器都归他管。

## 零件2：AVFilter —— 机器图纸（定义"这台机器能干吗"）

前面说了，它是**只读的说明书**。一张图纸上印着什么？PDF 标了重点的三样：

1. **名字**（`name`）：比如 "scale"、"overlay"。别人（命令行或代码）**靠这个名字去找图纸**。
2. **几个进料口**（`inputs`）
3. **几个出料口**（`outputs`）

图纸上还印着"这台机器出厂自带的本事"（回调函数），也就是前面说的**"到时候叫我"的电话**，主要有这几个：

| 图纸上写的本事    | 大白话                             | 什么时候被叫                           |
| ----------------- | ---------------------------------- | -------------------------------------- |
| `init`            | 开机自检                           | 机器一造好、参数设好后，叫一次         |
| `query_formats`   | 报一下"我进口出口分别支持什么格式" | 协商格式前叫（可能叫好几次）           |
| `process_command` | 接受外部命令                       | 你运行时想改机器参数时叫               |
| `activate`        | **统一干活入口**（新版）           | 机器该干活了就叫它（后面纠正部分细讲） |
| `priv_size`       | 这台机器需要多大的私人储物柜       | 造机器时用来分配内存                   |

> **一句话**：AVFilter = 一张贴在车间墙上的**机器说明书**，全工厂共用一份，谁都不会去改它。

## 零件3：AVFilterContext —— 正在干活的机器（管"它和外界的联系"）

这是**真正在车间里干活的那台机器**，也是你代码里主要操作的东西。一台机器身上挂着什么？PDF 标了重点：

1. **它按哪张图纸造的**（`filter` 指针，指向说明书）
2. **它叫什么名字**（`name`）——注意：可以有两台同名同型号的机器，靠名字/序号区分
3. **进料口**（`input_pads`）、**出料口**（`output_pads`）
4. **进料口的传送带**（`inputs`）、**出料口的传送带**（`outputs`）——注意，插口是"规格描述"，传送带才是"真接好的管子"
5. **它自己的私人储物柜**（`priv`）：这台机器自己的参数都放这儿（比如缩放机"缩到一半"这个参数）
6. **它属于哪个车间**（`graph`）

> **一句话**：AVFilterContext = **一台具体、带参数、正在工作的机器**。图纸是大家的，机器是你个人的。

## 零件4：AVFilterPad —— 插口（定义输入/输出接口）

插口上写了两件事：**这个口是进还是出**，以及**这个口上挂了几个"电话"**：

- **进料口上的电话**：
  - `filter_frame`：**"上游把一张照片推下来了，快来接！"** —— 你在这加工照片
  - `get_video_buffer` / `get_audio_buffer`：**"给你一个空相框，你往里填数据"** —— 分配缓冲用
- **出料口上的电话**：
  - `request_frame`：**"下一台机器在跟我要照片了，快产出一张给我！"**
  - `poll_frame`：**"你现在能立刻给我几张？"**
- 两个口都有的：
  - `config_props`：**"管道属性定下来了（宽高定了），你确认一下"** —— 注意格式（像素格式）不在这儿定，是前面说的"协商"定的
- 两个特殊标记：
  - `needs_fifo`：这台机器有延迟、要攒一批再处理，就让系统**在进口前自动加一个缓冲箱**
  - `needs_writable`：这台机器会**改照片内容**，需要"可写"的帧，必要时系统会帮你复制一份再给它，免得把原件改坏

这里有个特别关键、也特别容易混的点，**推 vs 拉**，我给你讲透：

> **推（filter_frame）**：上游机器做完一张，**主动顺着传送带扔给你**，"接着！"——你在接收电话里干活。
> **拉（request_frame）**：你没货可出了，就**朝上游喊**："喂，再给我一张！"——上游在它的产出电话里干活。
> 一台机器，通常**进口**上挂了"接收电话"（别人推给我），**出口**上挂了"要货电话"（我去拉上游）。

> **一句话**：AVFilterPad = 机器上一个插口的"规格牌"，写着这口是进是出、谁来叫我。

## 零件5：AVFilterLink —— 传送带（连接两台机器）

这是"连接"的核心，PDF 标了重点的四个字段：

- `src` + `srcpad`：**这头连的是哪台机器的哪个出料口**
- `dst` + `dstpad`：**那头连的是哪台机器的哪个进料口**
- `graph`：**这条传送带属于哪个车间**

一根传送带上还写着很多"运输约定"（这些就是之前说的协商结果，PDF 里都有）：
- **运的是视频还是音频**（`type`）
- 视频的**宽、高**（`w`、`h`），音频的**声道数、采样率**（`channels`、`sample_rate`）
- 双方最终敲定的**格式**（`format`）
- 照片上的**时间戳用什么尺子量**（`time_base`，就是"1 秒被切成多少份"）
- 协商时用的"备选清单"：`in_formats`/`out_formats` 就是**两边各自能接受的格式清单**，协商算法在这两个清单里找交集

**这里要提醒一句**（PDF 原文强调的）：传送带内部这些细节，**正常写应用代码的人不要去碰**，那是写滤镜本身的人才需要关心的。你作为"用滤镜的人"，只要会"接管子"和"喂料取料"就够了。

> **一句话**：AVFilterLink = 一根**真实的传送带**，把两台机器的口接起来，上面还标好了"运什么、什么规格、什么时间基准"。

## 零件6：AVFilterInOut —— 没接线的"预留接口清单"

这个不是干活的机器，是个**纸条**，专门在"用字符串建复杂流水线"时用（后面详细讲）。

它记的是：**这张流水线图纸上，还有哪个口是空着的，等着你从外面接进料口/出料口。** 纸条上写：哪个机器的第几个口、名字叫啥。

> **一句话**：AVFilterInOut = "还有几个洞没接水管"的**清单**，帮你把外面的水龙头（buffersrc/buffersink）接上去。

## 两个特殊的机器：buffer（入口）和 buffersink（出口）

这俩是流水线的**两头**，PDF 特意强调：

- **buffer（也叫 buffersrc）**：**原料入口**。你的原始照片就是从这台机器塞进流水线的。造它的时候要告诉它原料的规格（照片多大、什么格式、时间戳用什么尺子）。
- **buffersink**：**成品出口**。流水线加工完的照片从这儿拿出来。

> 整个流程永远是这样：`原料 → 入口机器(buffer) → 中间各种机器 → 出口机器(buffersink) → 成品`。

## 常用滤镜清单（PDF1 里提到）

- **scale**：缩放（照片放大缩小）
- **trim**：按帧截取（比如"只留第 10 到第 20 帧"）
- **overlay**：叠加（把一张照片叠在另一张上面，比如加字幕/台标）
- **rotate**：旋转
- **movie**：加载第三方视频当素材
- **yadif**：去隔行（老电视信号那种隔行扫描的修复）

## PDF1 最后的大例子：split → crop → vflip → overlay

这个图你肯定见过两次了（两篇 PDF 都有），是理解"滤镜图"的**标准入门图**，我拆到骨子里讲：

```
        [main]
input --> split ---------------------> overlay --> output
            |                              ^
           [tmp]                    [flip] |
            +-----> crop --> vflip --------+
```

**一步一步看**（把方括号当"标签"看，就是给传送带起个名字）：

1. `input`：就是入口机器 buffer，原料（一张完整的照片）进来。
2. `split`：这台机器很特别，**把一张照片复制成两份**，分成两路：
   - 一路叫 `[main]`（主路），原样不动，直接往前走。
   - 一路叫 `[tmp]`（临时路），拐去加工。
3. `[tmp]` 先进 `crop`（裁剪，比如把照片下半部分裁掉），再进 `vflip`（上下翻转），加工完的这路改名叫 `[flip]`。
4. 现在 `[main]`（原样照片）和 `[flip]`（下半部分被翻转的照片）两路，一起汇入 `overlay`（合成机，它有两个进口），叠在一起。
5. `output`：就是出口机器 buffersink，成品出去。

**对号入座**（PDF 原文点明的关系）：
- 图里**每个方框**（split/crop/vflip/overlay）= 一台机器 = 一个 **AVFilterContext**
- 图里**每条连线** = 一根传送带 = 一个 **AVFilterLink**
- **整张图** = 由 **AVFilterGraph** 这个大管家统一管理

# 三、PDF2：《FFmpeg Filter 补充内容》——教你怎么"建流水线、写指令"

这份 PDF 换了个角度：不讲内部零件了，讲**你作为使用者，怎么用**。核心就是"三层语法" + "两种建图方式"。

## 1. 先认识几个常用命令

- `ffmpeg -filters`：**列出你机器上 FFmpeg 支持的所有滤镜**。想看具体某个滤镜的说明书：`ffmpeg -h filter=rotate`（会显示它有几个输入口、几个输出口、支持哪些参数）。
- 最简单的例子：`ffmpeg -i input -vf scale=iw/2:ih/2 output`
  - `-vf` = video filter，视频滤镜的意思
  - `scale` = 缩放机
  - `iw/2:ih/2` = 宽（iw）减半，高（ih）减半 —— 就是把照片缩成一半

## 2. 三层语法：套娃结构（PDF 的重点，必须讲透）

从里到外一共三层，像**俄罗斯套娃**：

- **第1层：单个滤镜（filter）** —— 一台机器
- **第2层：滤镜链（filterchain）** —— 几台机器**用逗号串成一排**，前一台输出自动接后一台输入
- **第3层：滤镜图（filtergraph）** —— 几根链**用分号拼成一张网**，可以分叉、汇合

### 第1层：单个滤镜怎么写？

通用格式长这样：

```
[输入标签1][输入标签2] 滤镜名 = 参数 [输出标签1][输出标签2]
```

**标签是什么**？就是你给传送带**起的名字**，用方括号包着。
- 写在滤镜**前面**的标签 = 这台的**输入**从哪来
- 写在滤镜**后面**的标签 = 这台的**输出**叫什么名字，方便别人引用

**参数 `=参数` 有三种写法**（PDF 讲得细，别漏）：

1. **"参数名=值"格式**，冒号分隔：
   ```
   scale=w=iw/2:h=ih/2
   ```
   直译：宽=减半，高=减半。

2. **只写值**，按"说明书上的参数顺序"自动对应：
   ```
   scale=iw/2:ih/2
   ```
   因为 scale 说明书上前两个参数正好是"宽、高"，所以第一个值给宽、第二个值给高。

3. **混着写**：值必须在前，后面的"参数名=值"顺序随意：
   ```
   scale=iw/2:h=ih/2
   ```

### 第2层：滤镜链怎么写？

就是**用逗号**把几台机器串起来：

```
crop=iw:ih/2:0:0, vflip
```

意思：先裁剪（crop），裁完直接翻（vflip），前一个的输出自动喂给后一个。**逗号 = 串联**。

### 第3层：滤镜图怎么写？

就是**用分号**把几根链拼起来：

```
split [main][tmp]; [tmp] crop=..., vflip [flip]; [main][flip] overlay=...
```

分号 = "这里开一条新链"。几条规则（PDF 列得很细，我全给你翻成人话）：

1. **同名标签自动接上**：两个地方都出现 `[flip]`，FFmpeg 就把它们连起来。这就是为什么你能把不同链"接"起来。
2. **没写标签的输出，自动接下一个滤镜的第一个没写标签的输入**。PDF 给的例子：
   ```
   nullsrc, split[L1], [L2]overlay, nullsink
   ```
   split 有两个输出，overlay 有两个输入。split 的第一个输出标了 `[L1]`，overlay 的第一个输入标了 `[L2]`；**split 的第二个（没标）输出 → 自动接到 overlay 的第二个（没标）输入**。这就是"没贴标签的自动配对"。
3. **默认名字**：整条链第一个滤镜没写输入标签，就默认叫 `[In]`；最后一个滤镜没写输出标签，默认叫 `[out]`。
4. **有效性**：所有没打标签的口**必须都连上**，一个都不能剩，这张图才"有效"，FFmpeg 才会让你开工。

### 一个完整的命令行例子（两篇 PDF 共用的）

```
ffmpeg -i INPUT -vf "split [main][tmp]; [tmp] crop=iw:ih/2:0:0, vflip [flip]; [main][flip] overlay=0:H/2" OUTPUT
```

拆成三段（分号隔开）：
- `split [main][tmp]`：一台 split 机，默认输入，两个输出分别叫 main、tmp
- `[tmp] crop=iw:ih/2:0:0, vflip [flip]`：一根链——裁剪机接翻转机，翻转机输出叫 flip
- `[main][flip] overlay=0:H/2`：一台 overlay 合成机，两个输入 main 和 flip，默认输出

### 标签的实际用途例子：拆出 Y/U/V 三个分量

```
ffmpeg -i input.mp4 -filter_complex "extractplanes=y+u+v[y][u][v]" \
       -map "[y]" input_y.mp4 -map "[u]" input_u.mp4 -map "[v]" input_v.mp4
```

`extractplanes` 把一张照片拆成 Y（亮度）、U、V（颜色）三部分，分别输出到 `[y]`、`[u]`、`[v]` 三个标签；再用 `-map` 把每个标签单独存成一个文件。**这就是标签最直白的用处：给各路输出起名，然后分别取用。**

## 3. 两种"建流水线"的方式

### 方式一：简单场景——手把手一根一根接（PDF 叫"简单滤波过程"）

滤镜少时，代码里一步步搭，**五步口诀**：拿图纸 → 建车间 → 造机器 → 接传送带 → 开工。

```
第1步 拿图纸：avfilter_get_by_name("buffer")、avfilter_get_by_name("buffersink")、
              avfilter_get_by_name("你要的滤镜名")
第2步 建车间：avfilter_graph_alloc()
第3步 造机器：avfilter_graph_create_filter(...)   // 照图纸造，填上名字和参数
第4步 接传送带：avfilter_link(前一台机器, 口0, 后一台机器, 口0)  // 把出口0接到进口0
第5步 开工：avfilter_graph_config(...)   // 这一步才真正做格式协商、把所有传送带初始化好
```

注意**第5步**：前面几步只是"摆好了图纸和机器"，**没真正连起来**。`avfilter_graph_config` 一调用，FFmpeg 才做"协商格式、接通传送带、正式就绪"。就像你把机器都搬到车间但还没通电，config 就是**按总开关**。

### 方式二：复杂场景——写一句话让 FFmpeg 自己搭（PDF 叫"复杂滤波过程"）

滤镜一多，一根根手接太累。于是你直接写一句"图纸描述字符串"，让 FFmpeg 自己解析、自己搭。PDF 的例子：

```
[0]trim=start_frame=10:end_frame=20[v0];\
[0]trim=start_frame=30:end_frame=40[v1];\
[v0][v1]concat=n=2[v2];\
[1]hflip[v3];\
[v2][v3]overlay=eof_action=repeat[v4];\
[v4]drawbox=50:50:120:120:red:t=5[v5]
```

逐行翻译：
- `[0]` = 第 0 号原料口（第一个 buffer 入口）；`[1]` = 第 1 号原料口
- 第1行：从第0号口截取第 10~20 帧，输出 `[v0]`
- 第2行：从第0号口截取第 30~40 帧，输出 `[v1]`
- 第3行：把 `[v0]` 和 `[v1]` 两段**首尾接起来**（concat，拼接到一起），输出 `[v2]`
- 第4行：把第1号口做水平翻转，输出 `[v3]`
- 第5行：把 `[v2]` 和 `[v3]` 叠加（eof_action=repeat 是说一路没画面了就先重复最后一张，等另一路），输出 `[v4]`
- 第6行：在 `[v4]` 上画个红色方框，输出 `[v5]`

**关键点**：标签 `[0]`、`[1]` 从头到尾没有别的输出接上它们，所以它们是**外部输入口**——你要亲手接 buffer 入口进去；`[v5]` 没人接，是**外部输出口**——你要亲手接 buffersink 出口。**怎么知道哪些口空着？** 这就是前面说的 `AVFilterInOut` 清单的用武之地了。

代码流程：

```
第1步：avfilter_graph_alloc()               // 建车间
第2步：avfilter_graph_parse2(图, 字符串, &inputs, &outputs)
      // FFmpeg 解析字符串，自动搭好内部结构，
      // 然后把"还空着的输入口"放进 inputs 链表，
      // "还空着的输出口"放进 outputs 链表
第3步：遍历 inputs 链表 → 每个空口接一台 buffer 入口机器
第4步：遍历 outputs 链表 → 每个空口接一台 buffersink 出口机器
第5步：avfilter_graph_config(...)           // 开工
```

**这里的 `inputs` / `outputs` 就是 `AVFilterInOut` 链表**——它就是"预留接口清单"。用完记得 `avfilter_inout_free()` 释放掉（不然内存泄漏）。

> 一句话对比两种方式：**方式一** = 手动一台一台接，适合少；**方式二** = 写一句话让 FFmpeg 自动搭，适合复杂。日常开发 90% 用方式二。

## 4. 帧怎么送进去、怎么拿出来（最后一块拼图）

流水线搭好了，数据怎么流动？

- **送进去**：`av_buffersrc_add_frame(入口机器, 帧)` —— 把一张照片塞进入口
- **拿出来**：`av_buffersink_get_frame(出口机器, 帧)` —— 从出口取一张加工完的照片，**返回值 >= 0 说明取到了**

完整闭环就是：

```
解码出帧 → 塞进入口 buffer → 流水线加工 → 从出口 buffersink 取出 → 编码/显示
```

# 四、必须提醒你：这份 PDF 有几处已经过时了（用现在的 FFmpeg 8/9 为准）

PDF 是几年前的老课件，有几处**千万别照抄**：

1. **最关键的坑**：PDF 说用滤镜前要先调 `avfilter_register_all()` 注册——**这是错的，这个函数早没了**。
   从 FFmpeg 4.0 起滤镜改成"编译时自动注册"，不需要任何注册步骤；那套注册 API 在 2021 年彻底删除。[cite:dc2555f1-1][cite:dc2555f1-5]
   **现代写法就是直接 `avfilter_get_by_name()`，别的都不用管。**

2. **送帧 API 建议换新的**：`av_buffersrc_add_frame` 已标记弃用，推荐用 `av_buffersrc_add_frame_flags(入口, 帧, 0)`。

3. **滤镜干活模型升级了**：老模型是"推/拉回调"（filter_frame/request_frame），新模型是统一的 `activate()`——FFmpeg 反复叫它"该干活了"，它在里面自己检查情况、每次处理一步。看新源码时认 `activate` 就对了。

4. **版本现状**（你说的 ffmpeg8/9 方向没错，正好是当前最新）：[cite:195f0692-1]
   - FFmpeg 8.0 "Huffman"（2025年8月）、8.1 "Hoare"（2026年3月）→ 当前主推
   - FFmpeg 9.0 "Lei"（2026年8月）→ 刚发布的最新大版本 [cite:195f0692-2]
   - 7.1 "Péter" 是官方 LTS 长期维护版 → **生产环境求稳选它**
   - 7.0 的支持已于 2026年6月结束
   - **学习/开发直接用 8.x 就行**，上面讲的 API 在 8/9 里全部通用，唯一要躲的坑就是第1条那个已删除的注册函数。

# 最后给你一个"只记 5 句话"的收尾

1. **一张图纸（AVFilter）能造很多台机器（AVFilterContext）**，机器有进料口出料口（AVFilterPad），用传送带（AVFilterLink）串起来，归大管家（AVFilterGraph）统一管。
2. **数据永远**：入口 buffer → 机器们 → 出口 buffersink，`av_buffersrc_*` 送进去，`av_buffersink_get_frame` 取出来。
3. **命令行三层语法**：`滤镜`用逗号串成`滤镜链`，`滤镜链`用分号拼成`滤镜图`；方括号 `[名字]` 是给传送带起名，**同名就自动接上**。
4. **简单图**：五步手动搭（拿图纸→建车间→造机器→接带子→config 开工）；**复杂图**：写一句字符串，用 `avfilter_graph_parse2` 自动搭，再用 `AVFilterInOut` 清单把空口接上。
5. **别照抄老代码**：不用调 `avfilter_register_all`，用 `av_buffersrc_add_frame_flags`，认识新调度模型 `activate`。
