# README – FLV 到 H.264 Annex-B 裸流提取器

这是一个**专业、高效的 FLV 视频流提取工具**。  
它可以从 FLV 容器文件中分离出 **H.264 视频裸流**，并将其转换为标准的 **Annex‑B 格式**（每个 NAL 单元前添加起始码 `0x00 0x00 0x00 0x01`），输出为可直接播放或分析的 `.h264` 文件。

---

## 1. 用途

- **从 FLV 视频中提取纯视频数据**：许多直播平台、录像设备使用 FLV 格式封装，本工具可剥离出原始 H.264 码流。
- **将 FLV 中的 H.264 转为通用格式**：Annex‑B 是大多数 H.264 编码器、分析工具（如 Elecard StreamEye）和播放器（如 VLC、ffplay）直接支持的格式。
- **为后续处理做准备**：提取后的裸流可用于生成编码信息报表、合并、裁剪或转封装为其他容器（如 MP4）。
- **学习 FFmpeg 比特流过滤器**：展示如何使用 `h264_mp4toannexb` 过滤器完成格式转换，是理解视频封装格式转换的绝佳范例。

---

## 2. 你需要什么

### 2.1 系统环境
- **操作系统**：Windows、Linux、macOS 均可（程序使用标准 C++ 和 FFmpeg 跨平台库）。

### 2.2 必须安装的软件
- **FFmpeg 开发库**（版本 4.0 或更高）：
  - `libavformat`（用于解封装 FLV）
  - `libavcodec`（提供 H.264 编码参数和比特流过滤器）
  - 头文件路径需在编译时指定。
- **C++ 编译器**：支持 C++11 标准（因为使用了 `std::ofstream`、`std::string` 等）。

### 2.3 一个 FLV 格式的视频文件
输入文件必须包含 **H.264 视频流**（绝大多数 FLV 直播或录制文件都满足）。若包含其他编码（如 H.265），本程序会报错退出。

## 3. 程序能完成什么

| 功能点                         | 说明                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| **自动识别 FLV 中的 H.264 流** | 通过 `av_find_best_stream` 自动定位视频流，并检查其编码 ID 是否为 `AV_CODEC_ID_H264`。 |
| **格式转换（AVCC → Annex‑B）** | 将 FLV 内部存储的 AVCC 格式（每个 NAL 前带长度字段）转换为标准 Annex‑B（每个 NAL 前带起始码）。 |
| **嵌入 SPS/PPS 信息**          | 从 FLV 的 `extradata` 中提取序列参数集（SPS）和图像参数集（PPS），并在输出流开头生成包含这些 NAL 的起始码包，确保播放器能正确初始化解码器。 |
| **高效逐包处理**               | 按时间顺序读取每个视频帧，通过比特流过滤器转换后直接写入输出文件，不进行解码/编码，速度接近文件复制。 |
| **错误处理与资源清理**         | 对所有 FFmpeg 资源（上下文、过滤器、数据包）进行严格管理，并在失败时正确释放，避免内存泄漏。 |
| **简单命令行接口**             | 仅需两个参数：输入 `.flv` 路径和输出 `.h264` 路径，易于集成到脚本中。 |

### 典型运行示例
```bash
./flv_demux input.flv output.h264
```
执行后，`output.h264` 即为标准的 Annex‑B 裸流，可用 `ffplay output.h264` 直接播放（如果视频编码正常）。

## 4. 工作原理（通俗版）

### 4.1 FLV 中 H.264 的存储方式（AVCC 格式）
FLV（Flash Video）是一种流媒体容器，它存储 H.264 视频数据时，采用了一种称为 **AVCC** 的格式：
- 每个 NAL 单元（即视频编码的一小段数据）前面不是起始码，而是一个 **4 字节的大端长度字段**，表示该 NAL 单元的长度。
- 所有 NAL 单元连续存放，没有分隔符。
- 解码所需的参数集（SPS 和 PPS）并不放在每个帧中，而是单独保存在视频流的 `extradata`（额外数据）中，解码器必须在开始解码前先读取这部分。

这种方式的优势是节省空间（省去起始码的若干字节），但对直接播放或分析不够友好，因为缺少显式的同步标记。

### 4.2 Annex‑B 格式（标准裸流）
**Annex‑B** 是 H.264 标准建议的原始码流格式，特点是：
- 每个 NAL 单元前有 **起始码**：通常为 `0x00 0x00 0x00 0x01`（4 字节），也可用 `0x00 0x00 0x01`（3 字节）。
- SPS 和 PPS 作为独立的 NAL 单元（类型 7 和 8）出现在码流开头，解码器可以直接识别。
- 这种格式被大多数解码器（如 FFmpeg 的 `h264` 解码器）和播放器原生支持，无需额外参数。

### 4.3 转换过程（本程序的核心）
程序利用 FFmpeg 提供的 **比特流过滤器（BSF）** `h264_mp4toannexb` 来完成转换。这个过滤器就像一个“数据加工流水线”，会自动执行以下步骤：

1. **提取参数集**：从输入流的 `extradata` 中解析出 SPS 和 PPS。
2. **生成初始包**：在输出流的第一帧之前，插入包含 SPS 和 PPS 的 NAL 单元（带起始码），确保解码器首先获得这些关键信息。
3. **长度替换**：对每个视频帧数据包，将原有的 4 字节长度前缀替换为起始码。
4. **处理防竞争字节**：必要时插入 `0x03` 以防止载荷中出现与起始码相同的序列（标准要求）。
5. **拆分/合并**：某些情况下，一个输入包可能包含多个 NAL 单元，过滤器会将其拆分成多个独立的 NAL 单元输出；反之也可能合并。

### 4.4 程序的执行流程（8 步详解）

1. **打开 FLV 文件**  
   `avformat_open_input` 读取文件头，识别为 FLV 格式，创建 `AVFormatContext`。

2. **获取流信息**  
   `avformat_find_stream_info` 读取一部分数据，获得视频流的编码参数（包括 `extradata`）。

3. **定位 H.264 视频流**  
   `av_find_best_stream` 自动选择视频流，并检查 `codec_id` 是否为 H.264。

4. **创建并初始化比特流过滤器**  
   - 通过 `av_bsf_get_by_name("h264_mp4toannexb")` 获取过滤器对象。  
   - 分配上下文，将视频流的编码参数复制到过滤器的输入参数中。  
   - 调用 `av_bsf_init` 完成初始化（此时已解析出 SPS/PPS）。

5. **打开输出文件**  
   使用 C++ 的 `std::ofstream` 以二进制模式创建输出文件。

6. **循环读取、过滤、写入**  
   - `av_read_frame` 从 FLV 中读取下一个数据包。  
   - 若属于视频流，则送入过滤器 `av_bsf_send_packet`。  
   - 用 `av_bsf_receive_packet` 循环接收转换后的包，直接写入输出文件。  
   - 每处理完一个包，调用 `av_packet_unref` 释放引用。

7. **刷新过滤器**  
   发送空包（`nullptr`）通知输入结束，然后继续接收所有缓存的输出包（可能还有未输出的数据）。

8. **释放资源**  
   按顺序释放数据包、过滤器上下文和输入格式上下文，输出文件自动关闭。

整个过程 **不解码也不编码**，只是改变数据包的封装格式，因此速度极快，且不会损失画质。

## 5. 如何编译和运行

### 5.1 安装 FFmpeg 开发库（以 Ubuntu/Debian 为例）
```bash
sudo apt update
sudo apt install libavformat-dev libavcodec-dev
```
其他系统请参考 FFmpeg 官方文档安装对应开发包。

### 5.2 编译（Linux/macOS）
```bash
g++ -std=c++11 -o flv_demux main.cpp \
    -lavformat -lavcodec -lstdc++ -pthread -lz -lm
```
（Windows 下需指定库路径和库文件名，例如 `avformat.lib` 等）

### 5.3 运行
```bash
./flv_demux input.flv output.h264
```
- 第一个参数：输入 FLV 文件路径。
- 第二个参数：输出 H.264 裸流文件路径。

### 5.4 验证输出
- 使用 `ffplay output.h264` 可直接播放（若视频流完整）。
- 使用 `ffprobe output.h264` 可查看码流信息（如帧数、分辨率等）。

## 6. 程序局限性 & 扩展建议

| 局限性              | 说明                                                         |
| ------------------- | ------------------------------------------------------------ |
| **仅支持 H.264**    | 如果 FLV 包含其他视频编码（如 H.265、VP9），程序会报错。可扩展支持其他编码的 BSF（例如 `hevc_mp4toannexb`）。 |
| **忽略音频**        | 只提取视频流，音频流被丢弃。若需要音频，可分别提取或使用 FFmpeg 命令行工具。 |
| **未处理时间戳**    | 输出文件不包含时间轴信息，但帧顺序保持不变，播放时按帧率显示（播放器默认 25fps）。 |
| **仅支持 FLV 输入** | 程序仅针对 FLV 封装设计，但可简单修改 `avformat_open_input` 支持其他容器（如 MP4、MKV），因为 BSF 同样适用。 |

### 你想继续扩展的话，可以：
- **支持更多输入格式**：只需移除对 FLV 的特定依赖，FFmpeg 可以自动识别大多数格式。
- **同时提取音频**：添加音频流输出，如输出为 AAC 或 MP3 文件。
- **添加进度显示**：根据读取的包数量或文件大小输出进度信息。
- **支持命令行参数选项**：例如指定视频流索引、设置输出帧率等。
