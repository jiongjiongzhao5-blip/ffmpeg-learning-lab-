# README – AAC 音频流提取器（添加 ADTS 头）

这是一个**简洁、实用的 AAC 音频提取工具**。  
它可以将任意多媒体文件（MP4、FLV、MKV、AVI 等）中的 **AAC 音频流**提取出来，并保存为 **标准的 `.aac` 文件**（每个音频帧都带有 ADTS 头），可以直接被大多数播放器识别播放，也可用于后续编码处理。

---

## 1. 用途

- **从视频文件中剥离纯音频**：例如，你有一个 MP4 视频，想只保留背景音乐或人声，并存为独立的音频文件。
- **将容器内的 AAC 转为裸流格式**：很多播放器或硬件设备要求 AAC 音频必须带有 ADTS 头部才能解码，本程序自动添加这些头部，输出文件可直接播放。
- **学习 FFmpeg 中“比特流过滤器（Bitstream Filter）”的用法**：这是一个很好的入门示例，展示了如何在不进行解码/编码的情况下，修改数据包的封装格式。

---

## 2. 你需要什么

### 2.1 系统环境
- 支持 **Windows、Linux、macOS** 等主流操作系统。

### 2.2 必须安装的软件
- **FFmpeg 开发库**（版本 4.0 或更高）：
  - 核心库：`libavformat`（解封装）、`libavcodec`（编解码参数）、`libavutil`（工具函数）
  - 比特流过滤器：`libavcodec/bsf.h`（用于 `aac_adts` 过滤器）
- **C++ 编译器**：支持 C++11 标准（因为使用了 `std::unique_ptr` 和 lambda 风格的删除器）。

### 2.3 一个包含 AAC 音频的媒体文件
输入文件可以是任何 FFmpeg 能识别的封装格式，只要其中包含 **AAC 编码** 的音频流（绝大多数现代 MP4、FLV、MKV 都符合）。

## 3. 程序能完成什么

| 功能点                   | 说明                                                         |
| ------------------------ | ------------------------------------------------------------ |
| **自动寻找 AAC 流**      | 遍历输入文件的所有流，根据编码 ID（`AV_CODEC_ID_AAC`）定位第一条 AAC 音轨。 |
| **提取所有音频帧**       | 读取文件中的每一个数据包（Packet），仅处理属于 AAC 流的包，忽略视频、字幕等。 |
| **添加 ADTS 头部**       | 使用 FFmpeg 内置的 `aac_adts` 比特流过滤器，为每个 AAC 原始帧自动生成并添加 7 字节的 ADTS 头部（包含采样率、声道数、帧长度等必要信息）。 |
| **输出标准 `.aac` 文件** | 将添加头部后的帧连续写入文件，形成一个符合 ISO/IEC 13818‑7 标准的 ADTS 流文件。 |
| **自动资源管理**         | 利用 C++ 智能指针（`unique_ptr`）管理 FFmpeg 上下文、包和文件句柄，确保不会发生内存泄漏或资源未释放。 |
| **错误提示清晰**         | 将 FFmpeg 错误码转换为人类可读的字符串，方便定位问题。       |

### 典型用法示例
```bash
./aac_extractor video.mp4 output.aac
```
执行后，`output.aac` 就可以用 VLC、ffplay 或任何支持 AAC 的播放器直接打开收听。

## 4. 工作原理（通俗版）

### 4.1 媒体文件里的音频长什么样？
多媒体文件（比如 MP4）是一个“集装箱”，里面装着：
- 视频流（H.264 / H.265 等）
- 音频流（AAC、MP3 等）
- 字幕、章节等

音频数据被分割成一个个**数据包（Packet）**，每个包包含一段压缩后的音频采样（比如 1024 个样本点）。  
对于 AAC 编码，裸数据（称为 **Raw AAC**）本身没有文件头信息，播放器无法仅凭这些数据知道采样率、声道布局等。因此，MP4 等容器会在文件头部（`extradata`）存储这些参数，播放器先读头部再读包。

### 4.2 为什么要加 ADTS 头？
当我们想把 AAC 单独保存成一个 `.aac` 文件时，如果直接写入裸 AAC 数据，播放器无法识别。  
**ADTS（Audio Data Transport Stream）** 是一种简单的流格式，它在每个 AAC 帧前添加一个 7 字节的头部，包含：
- 同步字（0xFFF）
- 编解码类型（AAC LC、HE-AAC 等）
- 采样率索引
- 声道数
- 帧长度（包含头部和数据）

这样，播放器每读取一个帧，都能从头部得知如何解码，从而可以独立播放整个流。

### 4.3 本程序的处理流程（6 步详解）

1. **打开输入文件**  
   `avformat_open_input` 读取文件头，识别封装格式，填充 `AVFormatContext`。

2. **获取流信息**  
   `avformat_find_stream_info` 会读取一小部分数据，确认每个流的编码参数（如 AAC 的 `extradata`），并存放到 `codecpar` 中。

3. **查找 AAC 流**  
   遍历所有流，检查 `codecpar->codec_id == AV_CODEC_ID_AAC`，找到第一个匹配的流索引。

4. **创建并初始化“aac_adts”过滤器**  
   - 通过 `av_bsf_get_by_name("aac_adts")` 获取过滤器对象。  
   - 分配过滤器上下文 `AVBSFContext`，并将音频流的编码参数（`codecpar`）复制给过滤器的 `par_in`。  
   - 调用 `av_bsf_init` 完成初始化。此时，过滤器已经知道采样率、声道数、profile 等信息，可以正确构造 ADTS 头。

5. **循环读包→送过滤器→写输出**  
   - 用 `av_read_frame` 不断读取原始数据包。  
   - 只保留音频流的数据包，送入过滤器（`av_bsf_send_packet`）。  
   - 用 `av_bsf_receive_packet` 接收处理后的新包，这个包现在已经带上了完整的 ADTS 头。  
   - 将新包的 `data` 和 `size` 直接写入输出文件。  
   - 释放包引用，继续循环。

6. **冲刷过滤器**  
   发送 `nullptr` 给过滤器，表示输入完毕。再次调用 `av_bsf_receive_packet` 直到返回 `AVERROR_EOF`，确保所有缓存的包都被输出（有些过滤器可能内部有队列）。

### 4.4 为什么不需要解码？
整个过程中，我们**完全没有调用解码器**，只是对压缩数据包进行“包装”修改。这大大降低了 CPU 开销，速度极快（几乎等同于文件复制）。

### 4.5 资源管理（RAII）
本程序用 C++ 的 `std::unique_ptr` 管理了三种资源：
- `AVFormatContext`（通过 `avformat_close_input` 释放）
- `AVBSFContext`（通过 `av_bsf_free` 释放）
- `AVPacket`（通过 `av_packet_free` 释放）
- 文件 `FILE*`（通过 `fclose` 释放）

因此，即使发生异常或中途返回，所有资源都会自动清理，绝对安全。

## 5. 如何编译和运行

### 5.1 安装依赖（以 Ubuntu/Debian 为例）
```bash
sudo apt update
sudo apt install build-essential libavformat-dev libavcodec-dev libavutil-dev
```
其他系统请参照 FFmpeg 官方文档安装开发包。

### 5.2 编译（Linux/macOS）
```bash
g++ -std=c++11 -o aac_extractor main.cpp \
    -lavformat -lavcodec -lavutil \
    -pthread -lz -lm
```
（如需链接其他库，请根据你的 FFmpeg 编译配置调整）

### 5.3 运行
```bash
./aac_extractor input_video.mp4 output.aac
```
- 第一个参数：输入文件路径（支持多种格式）
- 第二个参数：输出 `.aac` 文件路径

### 5.4 验证输出
可以使用 `ffplay output.aac` 播放，或用 `ffprobe output.aac` 查看信息。

## 6. 程序局限性 & 扩展建议

| 局限性                     | 说明                                                         |
| -------------------------- | ------------------------------------------------------------ |
| **只提取第一条 AAC 流**    | 如果文件包含多条 AAC 音轨（如多语言），程序只处理第一个。可扩展为通过参数选择流索引。 |
| **不支持非 AAC 音频**      | 若音频是 MP3、AC‑3 等，程序会报错退出。可增加对其他编码的支持（使用对应的 BSF，如 `mp3_header`）。 |
| **输出固定为 `.aac` 格式** | 只生成 ADTS 封装的 AAC，不支持打包成 MP4 或 M4A。如需 M4A，需改用复用器（muxer）。 |
| **未处理时间戳**           | 本程序只关心数据内容，不保留原始时间戳，因此输出文件无时间轴信息（但音频顺序不变）。 |

### 你想继续扩展的话，可以：
- **添加命令行选项**：例如 `--stream` 指定音频流索引，`--bitrate` 设置目标码率（但需重编码，更复杂）。
- **支持其他编码格式**：替换 `"aac_adts"` 为 `"h264_mp4toannexb"` 就能提取 H.264 视频流（但输出为裸流）。
- **输出为 MP4/M4A 容器**：使用 `avformat_write_header` 和 `av_interleaved_write_frame` 重新复用，得到 `.m4a` 文件。
- **增加进度显示**：根据读取的包数或文件大小显示进度条。

## 7. 总结

这个程序是一个**教科书级别的 FFmpeg 比特流过滤器使用示例**。它展示了：
- 如何打开媒体文件并找到指定流
- 如何创建和初始化比特流过滤器
- 如何发送/接收数据包实现数据流转换
- 如何优雅地管理 FFmpeg 资源（RAII）

即使你是初次接触 FFmpeg，阅读代码和本文档后，也能清晰地理解**从容器中提取纯净音频流**的完整过程。希望这个小工具能成为你音视频开发路上的好伙伴！
